Technical case study

One focused product. Full delivery discipline.

Nova Ledger is a focused Flutter application for manually tracking personal assets. Its deliberately small product scope made the complete engineering path visible: interface behavior, secure persistence, failure handling, automated validation, signed builds, store delivery, and real-device acceptance.

Architecture

  1. Flutter presentationAuthentication, portfolio, and privacy-support screens
  2. Domain contractsAuthentication and asset repository interfaces
  3. Supabase adaptersAuthentication plus Postgres persistence
  4. Database boundaryRow Level Security restricts every asset to its owner
  5. Release controlsFormat, analysis, 77 tests, coverage, secret checks, and signed artifacts
  6. Delivery evidenceGoogle Play, TestFlight, Android acceptance, and iPhone acceptance

What users can do

  • Create an account and confirm its email address.
  • Sign in to an owner-specific portfolio.
  • Add, edit, persist, and delete manually entered assets.
  • Hide every visible balance without altering stored values.
  • Reach privacy, support, and deletion information before or after sign-in.
  • Request account deletion through a documented operational process.

Data-protection model

  • Supabase Auth establishes the user session.
  • Postgres Row Level Security restricts select, insert, update, and delete operations to the authenticated owner.
  • Client code receives only public configuration; administrative credentials never ship in the app.
  • Secret scanning rejects protected paths and high-confidence credential formats.
  • Public policy, support, and deletion routes are checked against exact approved markers.
  • Reviewer and closed-test evidence stays private and de-identified.

Quality evidence

Authentication, portfolio behavior, persistence, failure handling, privacy navigation, deletion, and evidence integrity.

Two physical devices

Store-delivered Build 7 passed Android and iPhone acceptance.

Release verification also checks formatting, static analysis, store assets, release identity, artifact provenance, checksums, signing evidence, reviewer access, screenshot provenance, and account-deletion operations.

Release journey

  • Build 7 is active on Google Play's closed Alpha track.
  • Google Play independently accepted the at-least-12-testers threshold; the required 14-day continuity window is in progress.
  • Build 7 passed the Play-installed Moto G release gate.
  • Apple validated Build 7 in TestFlight, and it passed an eleven-check iPhone acceptance pass.
  • Apple Build 7 is Waiting for Review in App Store Connect with manual public release retained.

Engineering decisions

  • Repository interfaces: presentation code can be tested without coupling widgets to Supabase.
  • Database-enforced ownership: authorization remains effective even if a client path is wrong.
  • Explicit failure states: rejected sign-in, network failure, and failed mutations keep predictable UI and preserve known data.
  • Artifact identity: version, source revision, signature, checksum, and physical result must describe the same candidate.
  • Evidence contracts: release claims fail when required proof is missing, stale, inconsistent, or includes unresolved blockers.

Honest boundary

Nova Ledger is not a bank, brokerage, payment platform, or demonstration of enterprise scale. It demonstrates end-to-end ownership of a carefully scoped financial-data application and the discipline to protect users, test failure paths, preserve release identity, and communicate only what the evidence proves.
